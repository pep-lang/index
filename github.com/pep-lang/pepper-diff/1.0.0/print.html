diff

Diffs: the edits that turn one sequence into another, unified diffs of text, and applying them.

Bring it in with import diff.

  • myers, patience: an edit script between two arrays, as Edit runs
  • split_lines: text cut into lines that keep their endings
  • unified: the unified diff of two texts, as diff -u and git diff write it
  • apply: a unified diff applied to the text it was made from

Example

import diff;

main(): int {
    var old_text = "one\ntwo\nthree\n";
    var new_text = "one\n2\nthree\n";
    var patch = diff.unified(old_text, new_text, from_name = "a/n.txt", to_name = "b/n.txt");
    print(patch);
    # --- a/n.txt
    # +++ b/n.txt
    # @@ -1,3 +1,3 @@
    #  one
    # -two
    # +2
    #  three
    assert(diff.apply(old_text, patch).value() == new_text, "a round trip");
    return 0;
}

myers

myers<T>(a: T[], b: T[]): Edit[]

Returns a shortest edit script from a to b, found with Myers' algorithm in O((N + M) * D) time and O(N + M) space, where D is the number of elements deleted and inserted.

Elements compare with ==. Runs alternate between Equal and changes, and within a change a Delete comes before the Insert, as diff prints them. Applying the runs in order to a gives b.

Type parameters

  • T — the element type

Parameters

  • a — the first sequence
  • b — the second sequence

Returns

  • the runs, in order; empty when both sequences are empty

Example

var edits = diff.myers(["a", "b", "c"], ["a", "c", "d"]);
# Equal 0 0 1, Delete 1 1 1, Equal 2 1 1, Insert 3 2 1

patience

patience<T>(a: T[], b: T[]): Edit[]

Returns an edit script from a to b found with patience diff: it matches the elements that occur exactly once in each sequence, keeps the longest run of them that is in the same order in both, and diffs between those anchors the same way, falling back to myers where no element is unique. The result is often easier to read than Myers' when blocks move, but need not be the shortest.

Elements compare with == and are counted in a HashMap<T, ...>, so T must hash the way it compares (as String, the number types and [Equatable] structs do).

Type parameters

  • T — the element type

Parameters

  • a — the first sequence
  • b — the second sequence

Returns

  • the runs, in the same form as myers gives

apply

apply(text: String, patch: String): Result<String>

Applies the unified diff patch to text and returns the new text.

Each hunk must match text exactly where its @@ header says: every unchanged and removed line, line ending included. A hunk that does not is an error; apply never shifts a hunk or matches it fuzzily. Lines before the first @@ (diff --git, index, ---, +++) are skipped, and hunks must come in order without overlapping, as unified and git diff write them. A patch with no hunks gives text unchanged.

Parameters

  • text — the old text
  • patch — the diff, as unified writes it

Returns

  • the new text, or an error naming the line of the patch and of text where they disagree

Example

var patch = diff.unified("one\ntwo\n", "one\n2\n");
diff.apply("one\ntwo\n", patch).value();   # "one\n2\n"
diff.apply("one\nthree\n", patch).error().message;
# "patch line 3: hunk does not match line 2 of the text"

split_lines

split_lines(text: String): String[]

Splits text into lines, each keeping its "\n" (and a "\r" before it), so joining them gives text back. A last line with no "\n" is a line of its own; "" has no lines.

Parameters

  • text — the text to split

Returns

  • the lines, in order

Example

diff.split_lines("a\nb");   # ["a\n", "b"]

unified

unified( a: String, b: String, context: ulong = 3, from_name: String = "a", to_name: String = "b", algorithm: Algorithm = Algorithm.Myers ): String

Returns the unified diff that turns a into b: a --- and a +++ line naming the two sides, then one hunk for each group of changes, with context unchanged lines around it. A hunk starts with @@ -start,count +start,count @@, and its lines start with ' ' (unchanged), '-' (only in a) or '+' (only in b). A last line with no newline is followed by \ No newline at end of file. Changes at most 2 * context lines apart share a hunk, as in git diff.

Lines are compared whole, line endings included, so a "\r\n" line differs from the same line ending in "\n".

Parameters

  • a — the old text
  • b — the new text
  • context — how many unchanged lines to show around each change
  • from_name — what the --- line names a as, such as a/main.pep
  • to_name — what the +++ line names b as
  • algorithm — how to match the lines

Returns

  • the diff, or "" when the texts are equal

Example

diff.unified("one\ntwo\n", "one\n2\n");
# --- a
# +++ b
# @@ -1,2 +1,2 @@
#  one
# -two
# +2

Connection

struct Connection

A session with a PostgreSQL server.

Open one with connect. query and execute run one SQL statement with $1, $2, ... parameters through the extended protocol, so a parameter's value never becomes SQL; prepare keeps a statement on the server to run again; query_as<T> decodes each row into a struct. execute_script runs several statements through the simple protocol, with no parameters: never build its text from untrusted input.

A connection runs one query at a time and belongs to one thread or task at a time; share connections through a Pool. Inside async.run, a call that waits for the server parks only its task. The session ends with close(), or when the last reference to the connection goes away.

Example

import postgres;

struct User {
    var id: long;
    var name: String;
}

main(): int {
    var db = postgres.Connection.connect("postgres://app:secret@localhost/app").value();
    db.execute("INSERT INTO users (name) VALUES ($1)", [postgres.Value.Text("Ada")]).value();
    for (var user in db.query_as<User>("SELECT id, name FROM users").value()) {
        print($"{user.id}: {user.name}");
    }
    db.close();
    return 0;
}

Static methods

connect

static connect(config: Config): PgResult<Connection>

Connects and logs in to the server config names.

The login answers what the server asks for: SCRAM-SHA-256 (the default since PostgreSQL 14) or a cleartext password. MD5 is not supported. The session's client_encoding is UTF-8.

Parameters

  • config — the server, login, database and TLS settings

Returns

  • the connection, or the error: 08006 when the server cannot be reached or TLS fails, 28000 or 28P01 when the login fails, 3D000 when the database does not exist

connect

static connect(url: String): PgResult<Connection>

Connects to the server a connection URL names, as Config.parse(url) reads it.

Parameters

  • url — the connection URL, postgres://user:password@host/database

Returns

  • the connection, or the error, as for connect(Config)

close

close()

Ends the session: tells the server and closes the socket. Calling it again does nothing.

query

query(sql: String, parameters: Value[] = []): PgResult<Row[]>

Runs one statement with parameters and returns its rows.

$1 in sql is the first parameter, $2 the second, and so on; each one's type is the one the server infers from its use. The parameters travel apart from the SQL, so they cannot change what it does.

Parameters

  • sql — one SQL statement
  • parameters — its parameters, in order

Returns

  • the rows (none for a statement that returns none), or the server's error

Example

var rows = db.query("SELECT name FROM users WHERE id = $1", [postgres.Value.Integer(7)]).value();

execute

execute(sql: String, parameters: Value[] = []): PgResult<ulong>

Runs one statement with parameters and returns how many rows it changed or returned.

Parameters

  • sql — one SQL statement, such as an INSERT, UPDATE or DELETE
  • parameters — its parameters, in order

Returns

  • the row count the server reports (0 for a statement such as CREATE TABLE), or the server's error

execute_script

execute_script(sql: String): PgResult<void>

Runs sql, which may hold several statements separated by ;, through the simple query protocol, and discards any rows.

It takes no parameters: the text goes to the server as it is, so never build it from input you do not control. Use execute with parameters for that. Unless sql starts a transaction itself, its statements run in one implicit transaction, which a failure rolls back.

Parameters

  • sql — the statements, such as a schema

Returns

  • nothing, or the first statement's error

prepare

prepare(sql: String): PgResult<Statement>

Prepares sql on the server as a named statement to run many times.

Parameters

  • sql — one SQL statement with $1, $2, ... parameters

Returns

  • the statement, or the server's error (a syntax error shows here)

begin(): PgResult<void>

commit

commit(): PgResult<void>

Commits the open transaction (COMMIT). A transaction in which a statement failed rolls back instead, and commit returns an error with code 25P02.

Returns

  • nothing, or the error

rollback

Rolls back the open transaction (ROLLBACK).

Returns

  • nothing, or the server's error

transaction

transaction<T>(body: (Connection) => PgResult<T>): PgResult<T>

Runs body in a transaction: commits it when body returns a value, and rolls it back when body returns an error, which it then returns.

Type parameters

  • T — what body returns

Parameters

  • body — the work to do; it gets this connection

Returns

  • what body returned, or the error of body or the commit

Example

db.transaction<void>((db): postgres.PgResult<void> => {
    db.execute("UPDATE accounts SET balance = balance - 10 WHERE id = 1")?;
    db.execute("UPDATE accounts SET balance = balance + 10 WHERE id = 2")?;
    return postgres.PgResult<void>.ok();
}).value();

notifications

notifications(): Notification[]

Returns the notifications that have arrived, oldest first, and forgets them. They arrive while the connection reads from the server, so this returns those that came with earlier queries; wait_for_notification waits for one. A connection keeps at most Config.max_notifications of them (10,000 by default): past that, each new one drops the oldest, which dropped_notifications() counts.

Returns

  • the notifications, possibly none

dropped_notifications

dropped_notifications(): ulong

Returns how many notifications this connection has dropped, since it connected, because Config.max_notifications were already waiting. A count that grows means notifications() is not called often enough.

Returns

  • the number dropped

wait_for_notification

wait_for_notification(): PgResult<Notification>

Waits until a notification arrives on a channel this connection listens on, and returns it; returns at once when one is queued. Inside async.run the wait parks only this task.

Returns

  • the oldest notification, or the error that ended the wait

Statement

struct Statement

A statement prepared on the server with Connection.prepare, to run many times with different parameters.

Example

var insert = db.prepare("INSERT INTO hits (path) VALUES ($1)").value();
for (var path in paths) {
    insert.execute([postgres.Value.Text(path)]).value();
}
insert.close().value();

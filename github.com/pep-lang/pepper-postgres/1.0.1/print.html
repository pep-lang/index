postgres

A PostgreSQL client in pure Pepper: it speaks the server's wire protocol (version 3) over io and tls, with no libpq.

Bring it in with import postgres. Inside async.run, every call that waits for the server parks only its task, so many tasks can share a Pool. Every call that can fail returns a PgResult<T>, whose error holds the SQLSTATE code and the server's message.

  • Connection: a session: connect, query, query_as<T>, execute, execute_script, prepare, begin/commit/rollback, transaction, and LISTEN/NOTIFY through wait_for_notification
  • Config: the server, login, database and TLS settings, or parse a postgres:// URL
  • Statement: a prepared statement
  • Row: one result row: get by position or name, read<T> into a struct
  • Value: a parameter or column value
  • Pool, PooledConnection: connections that threads and tasks share
  • Notification: a message from NOTIFY
  • PgError, PgResult<T>: errors

Logins use SCRAM-SHA-256 or a cleartext password, as the server asks; MD5 is not supported. Queries with parameters go through the extended protocol, so a parameter's value never becomes SQL. execute_script sends its text as it is: never build it from untrusted input.

Example

import postgres;

struct Book {
    var title: String;
    var year: long;
}

main(): int {
    var db = postgres.Connection.connect("postgres://app:secret@localhost/library").value();
    db.execute_script("CREATE TABLE IF NOT EXISTS books (title text NOT NULL, year int)").value();
    db.execute(
        "INSERT INTO books VALUES ($1, $2)",
        [postgres.Value.Text("Dune"), postgres.Value.Integer(1965)]
    ).value();
    for (var book in db.query_as<Book>("SELECT title, year FROM books").value()) {
        print($"{book.title} ({book.year})");   # Dune (1965)
    }
    return 0;
}

Config

struct Config

The settings of a connection: the server, the login, the database, and whether to use TLS.

Make one with the constructor and set fields, or parse a connection URL with parse.

Example

var config = postgres.Config("app", "secret");
config.host = "db.example.com";
config.database = "inventory";
config.tls = true;

Static methods

parse

static parse(url: String): PgResult<Config>

Parses a connection URL, postgres://user:password@host:port/database?sslmode=require, as libpq writes them (postgresql:// too). Every part but the host is optional, and percent-escapes are decoded.

sslmode require, verify-ca and verify-full set tls (which always verifies the certificate); disable, allow and prefer leave it off. sslrootcert sets root_certificate. Other parameters are ignored.

Returns

Connection

struct Connection

A session with a PostgreSQL server.

Open one with connect. query and execute run one SQL statement with $1, $2, ... parameters through the extended protocol, so a parameter's value never becomes SQL; prepare keeps a statement on the server to run again; query_as<T> decodes each row into a struct. execute_script runs several statements through the simple protocol, with no parameters: never build its text from untrusted input.

A connection runs one query at a time and belongs to one thread or task at a time; share connections through a Pool. Inside async.run, a call that waits for the server parks only its task. The session ends with close(), or when the last reference to the connection goes away.

Example

import postgres;

struct User {
    var id: long;
    var name: String;
}

main(): int {
    var db = postgres.Connection.connect("postgres://app:secret@localhost/app").value();
    db.execute("INSERT INTO users (name) VALUES ($1)", [postgres.Value.Text("Ada")]).value();
    for (var user in db.query_as<User>("SELECT id, name FROM users").value()) {
        print($"{user.id}: {user.name}");
    }
    db.close();
    return 0;
}

execute_script

execute_script(sql: String): PgResult<void>

Runs sql, which may hold several statements separated by ;, through the simple query protocol, and discards any rows.

It takes no parameters: the text goes to the server as it is, so never build it from input you do not control. Use execute with parameters for that. Unless sql starts a transaction itself, its statements run in one implicit transaction, which a failure rolls back.

Returns

  • nothing, or the first statement's error

    return postgres.PgResult<void>.ok();
}).value();

notifications

notifications(): Notification[]

Returns the notifications that have arrived, oldest first, and forgets them. They arrive while the connection reads from the server, so this returns those that came with earlier queries; wait_for_notification waits for one. A connection keeps at most Config.max_notifications of them (10,000 by default): past that, each new one drops the oldest, which dropped_notifications() counts.

Returns

  • the notifications, possibly none

dropped_notifications

dropped_notifications(): ulong

Returns how many notifications this connection has dropped, since it connected, because Config.max_notifications were already waiting. A count that grows means notifications() is not called often enough.

Returns

  • the number dropped

wait_for_notification

wait_for_notification(): PgResult<Notification>

Waits until a notification arrives on a channel this connection listens on, and returns it; returns at once when one is queued. Inside async.run the wait parks only this task.

Returns

  • the oldest notification, or the error that ended the wait

PgError

struct PgError

An error: one the server reported, or one the client met on its side (a lost connection, a failed login, a row that does not decode).

code is the SQLSTATE, five characters such as 23505 (unique_violation); see <https://www.postgresql.org/docs/current/errcodes-appendix.html>. The client's own errors use the class that fits them: 08006 (connection_failure) for a failed read or write, 08P01 (protocol_violation) for a message it cannot make sense of, 28000 (invalid_authorization_specification) for a login it cannot complete, and 22000 (data_exception) for a row read<T> cannot decode.

The SQLSTATE code, such as 42P01 for an undefined table.

What went wrong (relation "missing" does not exist).

What to do about it, when the server suggests something.

Pool

[Shared] struct Pool

A fixed set of connections to one server, shared between threads and tasks.

A Connection belongs to one thread or task at a time, so code that runs many at once shares a Pool. The pool is [Shared]: a closure passed to async.spawn or async.Thread.spawn may capture it. connection() lends one connection at a time and waits while all are in use; inside async.run the wait parks only the task. Each connection sits in an async.Mutex, so the compiler checks the block that locks it as it checks any with over a lock: nothing made from the Connection, such as a Statement, can outlive the block.

A connection goes back to the pool with any open transaction rolled back. One whose socket failed stays closed; its next query returns an error with code 08003.

Example

import async;
import postgres;

main(): int {
    var config = postgres.Config.parse("postgres://app:secret@localhost/app").value();
    var pool = postgres.Pool.open(config, 4).value();
    async.run(() => {
        var tasks = Array<async.Task<void>>();
        for (var i in 0..8) {
            tasks.append(async.spawn<void>(() => {
                with (var lease = pool.connection()) {
                    with (var db = lease.lock()) {
                        db.execute("INSERT INTO hits DEFAULT VALUES").value();
                    }
                }
            }));
        }
        for (var task in tasks) {
            task.join();
        }
    });
    return 0;
}

connection

connection(): PooledConnection

Takes a connection nothing else is using, waiting while all are in use, for a with header. The block's binding is the connection's lock; lock it with an inner with to reach the Connection. The connection goes back to the pool when the outer block ends, by any path.

Returns

  • the lease on one connection

Panics

  • if the pool's connections are gone, which cannot happen while the pool is alive

Example

with (var lease = pool.connection()) {
    with (var db = lease.lock()) {
        db.execute("DELETE FROM sessions WHERE expires < now()").value();
    }
}   # the connection is back in the pool

PooledConnection

[Isolated] struct PooledConnection

One connection of a Pool, lent to the code that took it with Pool.connection(), which a with block holds.

enter() hands the block the connection's async.Mutex<Connection>; destroying the lease rolls back any transaction left open and gives the connection back to the pool. It is [Isolated]: it can only be the scope of a with header, so it cannot be kept past the block.

Value

enum Value

A value sent as a query parameter or read from a column.

A column decodes by its type: boolean to Bool; smallint, integer, bigint and oid to Integer; real and double precision to Real; bytea to Bytes; SQL NULL to Null. Every other type, such as numeric, text, date, uuid or json, is Text in PostgreSQL's text form, which the caller parses as it needs ("12.50", "2026-10-20").

A parameter's type is the one the server infers from where it is used, so Text("42") works for an integer parameter too, and Bytes is sent as binary.

Example

import postgres;

var parameters = [postgres.Value.Integer(1), postgres.Value.Text("Ada"), postgres.Value.Null];

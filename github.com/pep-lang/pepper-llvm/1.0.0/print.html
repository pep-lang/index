llvm

Bindings to LLVM for building IR and compiling it to object files, in Pepper types that free what they own.

A Context owns types and constants; a Module holds functions and globals; a Builder appends instructions to a function's blocks; a TargetMachine optimizes a module and compiles it to an object file, for the host or any triple a backend of the LLVM library handles. Those four free their LLVM object when the last reference goes away (each holds a Handle). Type, Value, BasicBlock and Attribute are plain handles, valid while their context and module are alive.

For what the wrappers do not cover, the llvm.llvm_c module declares the C functions themselves; every wrapper exposes its LLVM-C handle as ref.

Example

import llvm;

main(): int {
    var context = llvm.Context();
    var module = llvm.Module(context, "demo");
    var i32 = context.int32_type();
    var add = module.add_function("add", llvm.Type.function(i32, [i32, i32]));
    var builder = llvm.Builder(context);
    builder.position_at_end(context.append_block(add, "entry"));
    builder.return_value(builder.add(add.param(0), add.param(1), "sum"));
    module.verify().value();

    var machine = llvm.TargetMachine.host().value();
    machine.configure(module);
    machine.emit_to_file(module, "demo.o").value();
    return 0;
}

Builder

struct Builder

An instruction builder (LLVMBuilderRef). Move it to a block with position_at_end, then each call appends one instruction there and returns its result. It is disposed when the last reference to it goes away.

Every method that makes a value takes an optional name for it (%sum in IR); without one LLVM numbers it (%0).

Example

var context = llvm.Context();
var module = llvm.Module(context, "main");
var i32 = context.int32_type();
var add = module.add_function("add", llvm.Type.function(i32, [i32, i32]));
var builder = llvm.Builder(context);
builder.position_at_end(context.append_block(add, "entry"));
builder.return_value(builder.add(add.param(0), add.param(1), "sum"));

Context

struct Context

An LLVM context (LLVMContextRef), which owns the types and constants of the modules built in it. It is disposed when the last reference to it goes away; a Module or Builder made from it holds a reference, so it outlives them.

A context is not thread-safe: use each one, and everything made in it, from one thread.

Example

var context = llvm.Context();
var i32 = context.int32_type();
var answer = i32.const_int(42);   # i32 42

Makes the debug info of one module (LLVMDIBuilderRef). Make one per module, describe the compile unit, then each function, type and variable, attach locations to instructions, and call finalize() before verifying or emitting the module.

Adds a module, which the JIT compiles when one of its symbols is looked up. The JIT takes the module over: afterwards module is empty (is_owned() is false) and must not be used.

Parameters

  • module — a module made in a thread-safe context

Returns

  • Ok, or an Err when the module's context is not thread-safe or a symbol is defined twice

Panics

  • if module was already given to a JIT

lookup

lookup(name: String): Result<__ptr<void>>

Compiles what a symbol needs, and returns its address. Cast it to the C function pointer type matching the function's signature (as extern (int) => int) to call it.

Parameters

  • name — the function's or global's name

Returns

  • the address, or an Err when no added module or the program defines name

llvm.llvm_c

Raw bindings to the LLVM C API (LLVM-C): one extern per C function, with LLVM's own names and C's types.

Most programs use the llvm module instead, which wraps these in Pepper types that free what they own. Import llvm.llvm_c for a function the wrappers do not cover yet; its handles are the ref field of the wrappers' types (llvm.Type, llvm.Value, llvm.Module.ref, ...).

Importing the module links LLVM 20 (see link.pep for each platform).

Source: llvm_c/module.pep

Re-exports

  • Everything link.pep exports.
  • Everything core.pep exports.
  • Everything target.pep exports.
  • Everything debug_info.pep exports.
  • Everything orc.pep exports.

llvm_c/core.pep

The parts of llvm-c/Core.h, Analysis.h and BitWriter.h that a compiler needs: contexts, modules, types, values, constants, basic blocks, the instruction builder, verification and bitcode output.

Each declaration is the C function of the same name, with C's types: every LLVM*Ref handle is void*, LLVMBool and the enums are int, unsigned is uint, and size_t and uint64_t are ulong. See the LLVM-C headers for what each does. Strings LLVM returns as char* are freed with LLVMDisposeMessage; a returned const char* is not.

Source: llvm_c/core.pep

Which LLVM library a program that imports llvm_c links, per platform.

The bindings are written against LLVM 20, the version the Pepper compiler itself builds with by default.

Creates a target machine for any triple a backend of the LLVM library handles, such as aarch64-apple-darwin, riscv64-unknown-linux-gnu, wasm32-unknown-unknown or x86_64-pc-windows-msvc. Registers every backend first (initialize_all_targets).

Parameters

  • triple — the target triple, such as aarch64-apple-darwin
  • cpu — the CPU name; empty for the target's generic CPU
  • features — the CPU features (+avx2,-sse4a); empty for the CPU's own
  • level — how hard code generation optimizes
  • reloc — how code addresses itself
  • code_model — which addresses code may reach directly

Returns

  • the machine, or an Err when no registered backend handles triple

values.pep

The handles a context owns: types, values (constants, functions, globals, instructions), basic blocks and attributes.

These are small value structs around an LLVM-C pointer (ref). They own nothing: each stays valid while the Context (and, for a function, global or instruction, the Module) it came from is alive, so keep those alive while you use them.

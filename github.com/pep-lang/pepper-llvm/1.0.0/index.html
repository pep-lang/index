llvm

llvm 1.0.0

LLVM 20 C API bindings: build IR, optimize it, emit object files, JIT

Pages

  • llvm: Bindings to LLVM for building IR and compiling it to object files, in Pepper types that free what they own.
  • builder.pep: Builder: appends instructions to a basic block.
  • context.pep: Context: owns LLVM's types and constants, and makes the types, blocks and attributes of everything built in it.
  • debug_info.pep: DebugBuilder: debug info (DWARF, or CodeView on Windows) for a module, so debuggers can map machine code back to source lines, functions, types and variables.
  • enums.pep: The LLVM-C enumerations the wrappers take and return, with LLVM's values.
  • ir_module.pep: Module: a unit of LLVM IR (functions and globals) that is verified, optimized and compiled to an object file.
  • jit.pep: Jit: compiles modules in memory and returns the addresses of their functions, to call from the running program.
  • llvm.llvm_c: Raw bindings to the LLVM C API (LLVM-C): one extern per C function, with LLVM's own names and C's types.
  • llvm_c/core.pep: The parts of llvm-c/Core.h, Analysis.h and BitWriter.h that a compiler needs: contexts, modules, types, values, constants, basic blocks, the instruction builder, verification and bitcode output.
  • llvm_c/debug_info.pep: The parts of llvm-c/DebugInfo.h a compiler needs to emit DWARF and CodeView: the DIBuilder, files, compile units, functions, types, variables, scopes and locations.
  • llvm_c/link.pep: Which LLVM library a program that imports llvm_c links, per platform.
  • llvm_c/orc.pep: The parts of llvm-c/Orc.h and LLJIT.h needed to compile modules in memory and call them: ORC's LLJIT, thread-safe contexts and modules, and resolving the process's own symbols.
  • llvm_c/target.pep: The parts of llvm-c/Target.h, TargetMachine.h, Error.h and Transforms/PassBuilder.h that a compiler needs: registering the host's backend, target machines, object emission, data layouts and the optimization pipeline.
  • target.pep: Targets: registering the host's backend, TargetMachine, and compiling a module to an object file.
  • values.pep: The handles a context owns: types, values (constants, functions, globals, instructions), basic blocks and attributes.

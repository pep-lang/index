semver

version.pep

One version, major.minor.patch with an optional prerelease and build metadata (1.0.0-beta.2+exp.sha.5114f85), and its order: Version and parse.

Source: version.pep

Version

struct Version

A version: major.minor.patch, with an optional prerelease after - and optional build metadata after +.

Versions order by the spec's precedence (section 11): compare and the operators <, <=, >, >=, == and != all follow it, so build metadata is ignored (1.0.0+a == 1.0.0+b) and a prerelease sorts before its release (1.0.0-rc.1 < 1.0.0). to_string() keeps the build.

Example

var versions = [semver.parse("1.10.0").value(), semver.parse("1.9.0").value()];
versions.sort((a, b) => a.compare(b));   # 1.9.0, 1.10.0

compare

compare(other: Version): int

Returns the order of this version and other by the spec's precedence: major, minor and patch numerically; then a release after any of its prereleases; then the prerelease identifiers left to right, numeric ones numerically and below alphanumeric ones, which compare in ASCII order, and a longer list after its prefix. Build metadata is ignored.

parse

parse(text: String): Result<Version>

Parses a version as the spec writes it: 1.2.3, 1.2.3-rc.1, 1.2.3+build.5, 1.2.3-rc.1+build.5.

It is strict: exactly three numbers with no leading zeros, no v prefix, no spaces, and prerelease and build identifiers that are not empty and hold only ASCII letters, digits and - (and in a prerelease, numbers with no leading zero). A tag such as v1.2.3 is parsed after dropping its v.

Parameters

  • text — the version

Returns

  • the version, or an error saying what is wrong

Example

var version = semver.parse("1.0.0-alpha.1").value();
assert(version.prerelease == "alpha.1", "the prerelease");
assert(semver.parse("1.2").is_err(), "three numbers");

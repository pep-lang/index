clipboard.pep

The clipboard: Clipboard copies text to it and reads text from it, through the OS's clipboard where the program runs locally, or through the terminal (OSC 52), which reaches the clipboard of the machine the user sits at, over SSH too.

Source: clipboard.pep

ClipboardBackend

enum ClipboardBackend

Where a Clipboard copies to and reads from.

Cases

Auto

Auto

System when the program runs locally and the OS has a clipboard it can reach, else Osc52. Locally means none of SSH_CONNECTION, SSH_CLIENT and SSH_TTY is set: over SSH the OS's clipboard is the remote machine's, which the user cannot paste from.

System

System

The OS's clipboard: on Windows, its own (CF_UNICODETEXT); on macOS, pbcopy and pbpaste; on Linux, wl-copy and wl-paste when WAYLAND_DISPLAY is set, else xclip or else xsel when DISPLAY is, each found on the PATH.

Osc52

Osc52

The terminal's: OSC 52 sequences written to standard output, which the terminal acts on, so it reaches the user's clipboard over SSH.

ClipboardError

[Value] enum ClipboardError

Why a Clipboard could not copy or read. None of them holds the clipboard's text, so they are safe to show or log.

Cases

NoBackend

NoBackend(reason: String)

There is no clipboard to use; reason says why, such as no wl-copy, xclip or xsel on the PATH, or standard output not a terminal for OSC 52.

TooLarge

TooLarge(limit: ulong)

The text is longer than limit bytes: a copy past the Clipboard's osc52_limit, or a reply past the reader's clipboard_limit.

TimedOut

TimedOut

The terminal did not answer an OSC 52 read in time. Most terminals turn reading the clipboard off, and answer nothing.

Failed

Failed(reason: String)

The OS's clipboard, or the program reaching it, refused; reason says how.

Clipboard

struct Clipboard

Copies text to the clipboard, and reads it, through the backend backend says (see ClipboardBackend): the OS's clipboard, or the terminal's through OSC 52. Auto, the default, is resolved once, when the Clipboard is made, so backend says which is in use.

Through OSC 52, copy writes ESC ] 52 ; c ; <base64> BEL to standard output, and the terminal sets its clipboard; nothing comes back to say whether it did. Most terminals allow it, some only after the user turns it on, and some cap its length (osc52_limit). read asks with ESC ] 52 ; c ; ? BEL, which most terminals refuse by not answering, so it waits at most timeout_ms and then fails with ClipboardError.TimedOut; it never hangs.

Inside tmux, the sequence reaches tmux, not the terminal: with set -g set-clipboard on in .tmux.conf, tmux sets its own buffer and passes the copy on to the terminal. GNU screen passes OSC 52 on only inside its own escape (ESC P ... ESC \) and cuts long ones short. This package writes the plain sequence and wraps it for neither, since tmux's set-clipboard makes that unneeded; under screen, use System.

The text copied or read is never put in an error or a log.

Example

import term;
import [ClipboardBackend] from term;

main(): int {
    var clipboard = term.Clipboard();
    var copied = clipboard.copy("hello");
    if (copied.is_err()) {
        print($"could not copy: {copied.error()}");
        return 1;
    }
    print(clipboard.backend == ClipboardBackend.System ? "copied" : "asked the terminal to copy");
    return 0;
}

Methods

copy

copy(text: String): Result<void, ClipboardError>

Copies text to the clipboard.

Through OSC 52 the terminal does not say whether it copied, so success means the request was written.

Parameters

  • text — the text to copy

Returns

  • nothing; NoBackend when the OS has no clipboard to reach or, for OSC 52, standard output is not a terminal, TooLarge past osc52_limit, or Failed when the OS refused

read

read(timeout_ms: int = 1000, input: InputReader = InputReader()): Result<String, ClipboardError>

Returns the text on the clipboard.

Through OSC 52 it asks the terminal, in raw mode (turned on while it waits, if it is not on), and waits at most timeout_ms for the answer, which input decodes. Other input that comes meanwhile, such as keys, stays in input for its next read, so pass the program's own InputReader. An answer that comes after the wait arrives there as an Event.ClipboardReply. A terminal that asks the user first (kitty can) may answer after the wait; with raw mode off by then the terminal shows the answer as typed text, so for such a terminal keep a RawMode on and pass a longer timeout_ms.

Parameters

  • timeout_ms — how long to wait for the terminal's answer, in milliseconds; the OS's clipboard answers at once
  • input — the reader the terminal's answer is read through

Returns

  • the text, empty when the clipboard holds none; NoBackend when there is no clipboard or, for OSC 52, standard input or output is not a terminal, TimedOut when the terminal does not answer, TooLarge past input's clipboard_limit, or Failed when the OS refused

term

keys.pep

Keys and the events beside them: Key, KeyEvent, Event, and the decoders KeyDecoder and InputDecoder, which turn the bytes a terminal sends in raw mode into key events, and mouse reports too. Decoding is pure: bytes in, events out, so it needs no terminal and works on bytes from anywhere.

KeyEvent

struct KeyEvent

One key press: the key, the character it typed, and the modifiers held.

A control character arrives as its letter with ctrl set: Ctrl+A is Key.Char with text "a". Modifiers come from the terminal: Ctrl, Alt and Shift with the arrows, Home, End and the other editing keys, Alt with any key (the terminal sends Escape first), and Shift with Tab.

InputDecoder

struct InputDecoder

Decodes the bytes a terminal sends in raw mode into Events: key presses (see KeyDecoder) and mouse reports, in xterm's SGR encoding (ESC [ < b ; x ; y M, or m for a release) and its older X10 one (ESC [ M and three bytes).

Feed it bytes as they arrive. A sequence split across reads is held until the rest comes, and a lone Escape is held until flush, as with KeyDecoder. A mouse report the decoder cannot read (a button past the third, a position of 0, a broken sequence) decodes as Key.Unknown; huge numbers are capped, never overflow.

Example

import term;
import [Event, MouseKind] from term;

var decoder = term.InputDecoder();
var events = decoder.feed("\x1B[<0;3;4Mx".bytes());
match (events[0]) {
    Mouse(mouse) => assert(mouse.kind == MouseKind.Down && mouse.column == 2, "a click"),
    Key(key) => panic("a mouse report"),
}

KeyDecoder

struct KeyDecoder

Decodes the bytes a terminal sends in raw mode into KeyEvents: UTF-8 characters, control characters, and the escape sequences of xterm and its kin (VT100, the Linux console, Windows' virtual terminal input) for the arrows, Home, End, Insert, Delete, Page Up and Down, and F1 to F12, with their modifiers. A mouse report is one Key.Unknown; use InputDecoder to read it.

Feed it bytes as they arrive. A sequence split across reads is held until the rest comes. A lone Escape looks like the start of a sequence, so it is held too: when no more bytes arrive soon (a few tens of milliseconds), call flush to decode it as the Escape key.

Example

import term;

var decoder = term.KeyDecoder();
var events = decoder.feed("\x1B[1;5Ax".bytes());
assert(events[0].to_string() == "Ctrl+Up", "an arrow with Ctrl");
assert(events[1].text == "x", "a character");

term

Interactive terminal programs: raw mode, key input, line editing with history, cursor control, and 16, 256 and true colors, on Linux, macOS (termios) and Windows (the Console API).

Bring it in with import term. Decoding keys (KeyDecoder) and editing lines (LineEditor) are pure, bytes in and events or text out, so they work and test without a terminal. Without one (input or output a pipe or a file), raw mode does nothing, lines are read plainly, and colors_enabled() is false.

  • RawMode, restore: raw mode on and off; the terminal is restored at exit and on a panic too
  • KeyReader, KeyDecoder, KeyEvent, Key: key presses
  • LineReader, LineInput, LineEditor, EditStatus, History: readline-style line editing
  • Style, Color, BasicColor, RESET, colors_enabled: colors and text styles
  • move_to, move_up and the other moves, CLEAR_SCREEN and the other sequences: the cursor and the screen
  • input_is_terminal, output_is_terminal, size, Size: the terminal itself

Example

import term;
import [BasicColor, Color, LineInput, Style] from term;

main(): int {
    var prompt = Style(foreground = Color.Basic(BasicColor.Green), bold = true);
    var reader = term.LineReader();
    while (true) {
        match (reader.read_line(prompt.paint("> ", term.colors_enabled()))) {
            Line(text) => {
                print($"you typed {text}");
            }
            Interrupted => {}
            EndOfInput => {
                return 0;
            }
        }
    }
}

KeyEvent

struct KeyEvent

One key press: the key, the character it typed, and the modifiers held.

A control character arrives as its letter with ctrl set: Ctrl+A is Key.Char with text "a". Modifiers come from the terminal: Ctrl, Alt and Shift with the arrows, Home, End and the other editing keys, Alt with any key (the terminal sends Escape first), and Shift with Tab.

KeyDecoder

struct KeyDecoder

Decodes the bytes a terminal sends in raw mode into KeyEvents: UTF-8 characters, control characters, and the escape sequences of xterm and its kin (VT100, the Linux console, Windows' virtual terminal input) for the arrows, Home, End, Insert, Delete, Page Up and Down, and F1 to F12, with their modifiers.

Feed it bytes as they arrive. A sequence split across reads is held until the rest comes. A lone Escape looks like the start of a sequence, so it is held too: when no more bytes arrive soon (a few tens of milliseconds), call flush to decode it as the Escape key.

Example

import term;

var decoder = term.KeyDecoder();
var events = decoder.feed("\x1B[1;5Ax".bytes());
assert(events[0].to_string() == "Ctrl+Up", "an arrow with Ctrl");
assert(events[1].text == "x", "a character");

LineEditor

struct LineEditor

A line being edited: the text, the cursor, and the history that Up and Down move through. handle applies one key; render gives the bytes that redraw the line.

The keys are readline's (Emacs mode):

  • characters insert at the cursor
  • Left, Right, Ctrl+B, Ctrl+F move one character; Ctrl or Alt with Left and Right, and Alt+B and Alt+F, move one word
  • Home, End, Ctrl+A, Ctrl+E go to the start and the end
  • Backspace and Ctrl+H delete before the cursor, Delete and Ctrl+D at it (Ctrl+D on an empty line ends input)
  • Ctrl+W and Alt+Backspace delete the word before the cursor, Ctrl+U everything before it, Ctrl+K everything from it
  • Up, Down, Ctrl+P, Ctrl+N recall older and newer history entries
  • Enter submits the line, Ctrl+C abandons it

Example

import term;

var editor = term.LineEditor();
for (var key in term.KeyDecoder().feed("helo\x1B[Dl\r".bytes())) {
    editor.handle(key);
}
assert(editor.text == "hello", "Left, then insert");
assert(editor.history.entries[0] == "hello", "Enter records it");

RawMode

struct RawMode

Raw mode: the terminal hands over each key as it is pressed, without echoing it, editing the line, or turning Ctrl+C into a signal, as an editor or a game needs. Making a RawMode turns it on; exit, or the last reference going away, turns it off again.

Use it in a with block, which turns raw mode off however the block ends. The terminal is also restored when the program ends while raw mode is on: at the end of main, on a panic, and on SIGTERM, SIGHUP, SIGINT or SIGQUIT (POSIX). process.exit ends the program without running exit handlers, so call restore() before it.

In raw mode on Linux and macOS, output is raw too: "\n" moves down without returning to the first column, so write "\r\n".

Without a terminal on standard input, raw mode does nothing and active is false. Raw mode is one setting of the whole terminal, so while one RawMode has it on, another is not active either.

Example

import term;

main(): int {
    with (var raw = term.RawMode()) {
        var keys = term.KeyReader();
        print(raw.active ? "press a key\r" : "not a terminal");
        var key = keys.read();
        if (!key.is_empty()) {
            print($"you pressed {key.value()}\r");
        }
    }
    return 0;
}

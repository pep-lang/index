TermBackend

struct TermBackend

The backend of a real terminal: it writes escape sequences to standard output through pepper-term, all of a frame's in one write, and holds raw mode (and, when asked, mouse reporting and bracketed paste) on while it lives. Make one with init.

Constructor

TermBackend()

construct(mouse: bool = false, paste: bool = false)

Makes the backend, turning raw mode on while it lives. init makes one and sets up the screen too.

Parameters

  • mouse — whether to turn mouse reporting on too: presses, releases, drags and the wheel
  • paste — whether to turn bracketed paste on too, so a paste arrives as one Event.Paste

TestBackend

struct TestBackend

A backend that keeps the screen as a Buffer, for tests: draw frames to it, then compare to_lines() (and cells' styles) with what they should be.

Example

import tui;
import [Paragraph, Terminal, TestBackend] from tui;

var backend = TestBackend(5, 1);
var terminal = Terminal(backend);
terminal.draw((frame) => {
    frame.render_widget(Paragraph("hi"), frame.area);
});
assert(backend.to_lines()[0] == "hi   ", "drawn");

Terminal

struct Terminal

A screen drawn a frame at a time, in immediate mode: each draw has the app draw the whole screen from its state, and writes to the backend only the cells that differ from the last frame. A change of the backend's size is noticed at the next draw, which then redraws everything.

Example

import tui;
import [Block, Terminal, TestBackend] from tui;

var terminal = Terminal(TestBackend(20, 5));
terminal.draw((frame) => {
    frame.render_widget(Block(title = "Hello"), frame.area);
});

});

copy

copy(text: String): Result<void, term.ClipboardError>

Copies text to the clipboard, through clipboard, a pepper-term Clipboard made at the first copy unless set (ClipboardBackend.Auto: the OS's clipboard when the program runs locally, else the terminal's, through OSC 52, which reaches the user's clipboard over SSH too). What the backend has not sent yet goes first, so the OSC 52 sequence is never written into the middle of a frame.

Through OSC 52 the terminal does not say whether it copied, so success means the request was written.

Parameters

  • text — the text to copy, such as a widget's selected_text()

Returns

  • nothing; a ClipboardError when there is no clipboard to reach, the text is past the OSC 52 limit, or the OS refused. Its to_string() holds none of the text, so it is safe to show

Example

# in the event loop, on Ctrl+Y: copy what is selected, and say
# in a status line if that failed
var copied = terminal.copy(state.selected_text());
if (copied.is_err()) {
    status = $"could not copy: {copied.error()}";
}

init

init(mouse: bool = false, paste: bool = false): Terminal

Sets up the terminal for a full-screen app and returns a Terminal that draws on it: raw mode on, the alternate screen, colors on, the cursor hidden, the screen blank. With mouse, mouse reporting is on too, and Events.next yields Event.Mouse; the terminal then keeps the mouse, so the user cannot select text with it (many terminals still select with Shift held). With paste, bracketed paste is on too, and a paste arrives as one Event.Paste rather than as typed keys.

Call restore when the app ends. The terminal is also restored when the program ends without it: at the end of main, on a panic, and on SIGTERM, SIGHUP, SIGINT or SIGQUIT (POSIX). process.exit runs no exit handlers, so call restore before it.

Call it before anything else turns pepper-term's raw mode on (a term.RawMode, a term.LineReader reading a line): its signal handlers would then stay in place of these, and a panic would leave the alternate screen up. To set the terminal up again after restore, let the old Terminal go first: its backend's raw mode, freed later, would turn the new one's off.

Parameters

  • mouse — whether to turn mouse reporting on: presses, releases, drags and the wheel
  • paste — whether to turn bracketed paste on

Returns

  • the terminal

Example

import tui;

main(): int {
    var terminal = tui.init(mouse = true, paste = true);
    # ... draw frames and read events ...
    tui.restore();
    return 0;
}

restore

restore()

Puts the terminal back as init found it: the main screen, the cursor showing, and raw mode, mouse reporting and bracketed paste off. Does nothing when it is already restored.

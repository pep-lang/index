LanguageServer

trait LanguageServer

A language server: one method per request or notification of the protocol. Only initialize is required. Every other request answers METHOD_NOT_FOUND until the server defines it, and every other notification is ignored, so a server defines just what its ServerCapabilities promise.

serve calls the methods one at a time on one thread, in the order the messages arrive, so a server's state needs no locks: a did_change is always applied before the request that follows it. Slow work, such as analyzing a program, can run on another thread, which hands its result back through a channel and Client.wake (see woken).

Client

[Shared] struct Client

The server's way to talk to the client: notifications it sends on its own, such as diagnostics, and wake, which brings work done on other threads back to the server's thread.

A Client is [Shared]: keep it in the server and hand it to the threads the server starts. Each message it sends is queued, so sending never waits for the client to read.

wake

wake()

Makes the message loop call the server's woken on the server's thread, after the messages already queued. A thread that finished work for the server puts its result where the server will look (a Channel the server owns) and then calls wake, so the server's state is only ever touched on its own thread.

serve_stdio

serve_stdio<S: LanguageServer>(make: (Client) => S): int

Runs a language server over standard input and output until the client sends exit or the input ends.

A thread reads standard input and another writes standard output, so the server's thread only handles messages, and a message sent from any thread goes out without waiting for the server.

Type parameters

  • S — the server type

Parameters

  • make — creates the server, given the client it talks back through

Returns

  • the process's exit code: 0 after shutdown then exit, 1 otherwise

serve

serve<S: LanguageServer>(make: (Client) => S, inbound: Channel<Inbound>, outgoing: Channel<String>): int

Runs a language server on the calling thread until the client sends exit or inbound delivers End.

Handles one inbound item at a time, in order: messages go to the server's method for them, and each Wake calls woken. Answers requests before initialize with SERVER_NOT_INITIALIZED and requests after shutdown with INVALID_REQUEST. serve_stdio connects the channels to standard input and output; tests can fill and read them directly.

Type parameters

  • S — the server type

Parameters

  • make — creates the server, given the client it talks back through
  • inbound — the client's messages, then End
  • outgoing — where messages for the client go, as JSON text, in order

Returns

  • the process's exit code: 0 after shutdown then exit, 1 otherwise
